# Skill 可见性、功能范围与任务入口设计

日期：2026-11-23。状态：**待实现设计**，不代表当前入口已完成改造。依据现有技能注册表、不可变版本、会话绑定、导读适配器与前沿任务链增量设计。当前实现见 [Skills](SKILLS.md)，执行配置见 [Runner 配置](RUNNER-CONFIGURATION.md)。

## 1. 产品约定

“选择 Skill”决定执行的能力，“要求模板”只补充本次指令。输入区的主要选择器必须来源于当前账号技能库，不能继续把硬编码快捷提问当作 Skill 展示。配置好的技能能在哪些功能里出现，由技能配置页管理。

本次需求中的“对比追踪”按现有产品的“论文比较”入口设计；持续跟进领域的任务仍归“前沿追踪”。未来新增功能通过稳定的入口 ID 注册，不依赖页面标题字符串。

## 2. 技能配置页面

在技能详情增加“使用范围”，与基本资料、版本、工具权限分区呈现。

| 功能入口 | 配置与反馈 |
| --- | --- |
| 论文阅读 · 智能体对话 | 控制阅读右栏 Skill 选择器中的展示与新任务使用 |
| 独立研究对话 | 控制无指定论文的研究会话入口 |
| 论文比较 | 控制多篇论文比较入口，不默认等于阅读对话 |
| 论文审查 | 控制单篇论文审查任务入口 |
| 前沿追踪 | 控制前沿主题的新任务与调度技能选择 |
| 阅读导读与自动批注 | 需要结构化导读契约，区别于普通对话输出 |

每个入口默认显示一个“展示并可用于新任务”开关。高级设置允许“展示但不可执行”，用于让用户看到缺少适配或暂不可用的原因；关闭展示时不能允许创建新任务。页面同时显示实际可用状态和具体阻塞原因，如技能已停用、版本未通过结构校验、缺少输出契约或模型不支持所需图片。

- 已有分类继续描述研究领域；使用范围描述产品功能，二者独立。
- 批量选择、清空、保存和取消均可操作；保存使用 expected_revision 防止覆盖他人的新设置。
- 上传 ZIP 安装时也能选择范围，追加版本需重新核验兼容性。包内建议仅作为预填项，不能自动新增可用范围或工具权限。
- 内置技能允许按账号隐藏入口；不修改共享代码或其他账号的可见性。
- 启用、停用、归档继续沿用现有全局状态。收起某入口不等于卸载技能。
- 预览区按功能展示实际菜单效果；保存配置与预览不执行模型。

## 3. 各入口的交互

### 阅读对话与独立对话

将“任务与模板”改为以“技能”为主的选择器：搜索、领域分类和当前入口筛选，展示名称、简介、版本、当前选中状态。仅列当前入口可见的技能，展示不可执行项的禁用原因；未配置技能时给出技能库入口。

选中 Skill 后显示该技能关联的要求模板及可编辑要求。移除 QUICK 中独立硬编码的快捷内容；确需保留“解释方法”等常用提示时，将其登记为对应 Skill 的模板，由技能管理页维护。通用模板明确标记为提示词，不伪装成另一项技能。

选择只修改待执行配置，不立即发起模型任务。点击发送后，按选定 Skill 的固定版本执行。Skill 按轮次固定版本，兼容的技能切换默认在同一会话继续；后端预检执行环境、方案、权限和材料，不能只改菜单名称。跨信任边界或 CLI 适配不支持时才明确创建分支/新会话，保留原历史。详见 [产品化会话设计](AGENT-PRODUCT-DESIGN.md#6-自定义-skill-的运行与会话)。

### 论文比较与审查

选择器分别读取 compare/review 范围的技能，平台检查比较至少两篇论文、审查至少一篇，并校验资料归属与可访问文件。技能名称包含“比较”不是兼容性依据。输出、证据和会话继续走现有管理层。

### 前沿追踪

主题配置页增加“执行 Skill”与版本选择，读取 frontier 范围。主题保存固定技能版本、适配器及配置修订；手动运行、定时任务使用同一绑定，不自动采用新的默认版本。候选与报告仍必须通过检索证据、身份去重、引用和批准流程。

将 frontier_monitor 从触发逻辑中的唯一固定技能，改为默认的兼容选项。自定义技能必须满足 frontier-report 契约和受限工具绑定才能替代；普通对话技能不能仅靠勾选范围就被用于前沿结构化任务。变更主题技能需明确保存新主题修订；已排队任务保持原快照，权限撤销仍按现有运行校验生效。

### 导读与自动批注

使用 guide 范围并复用现有导读技能候选校验；必须满足 reader_guide 工具、材料与结构化输出要求。普通 Markdown 对话技能不能直接生成可渲染批注。使用范围是候选条件，不能替代兼容检查。

## 4. 数据模型

以下是拟新增结构，迁移编号在实现时按仓库最新状态分配。

| 结构 | 关键字段 | 作用 |
| --- | --- | --- |
| 产品入口目录（代码注册） | id、label、task_kind、adapter、material_constraints | 注册 reader_chat、research_chat、compare、review、frontier、guide |
| skill_placements（账号业务库） | skill_id、surface_id、visible、allow_new_tasks、revision、updated_at | 按技能管理入口展示和新任务选择 |
| 技能版本适配信息 | skill_version_id、adapter_id、contract_version、validation_status | 记录实际兼容证据，不靠名称判断 |
| 任务/会话快照 | entry_context、skill_id/version/hash、placement_revision、adapter/contract | 保存首次执行来源与实际绑定 |
| 配置审计 | actor、skill、surface、before/after、revision、time | 追踪入口范围变更，不保存凭据 |

组合规则：allow_new_tasks 为 true 时 visible 必须为 true；缺失的入口配置按不可见、不可新建处理。实际可执行还要求全局启用、合法版本、适配通过、材料/账号绑定正确及原有工具授权成立。

Skill 模板继续引用技能及版本；不把完整 Skill 文本复制进每条模板。执行方案已绑定 Skill 时，选择器展示该绑定；切换技能需要兼容的执行方案或用户明确重新选择配置，不能保留不匹配方案后偷偷降级成普通聊天。

## 5. 拟议接口与统一解析

**以下接口尚未注册，不加入当前 OpenAPI 清单。**

| 拟议接口 | 契约 |
| --- | --- |
| GET /api/skills/surfaces | 入口目录、可用适配器与材料要求 |
| GET /api/skills/{id}/placements | 当前账号的入口设置、revision 和兼容状态 |
| PUT /api/skills/{id}/placements | 完整范围设置 + expected_revision；事务保存并审计 |
| GET /api/skills/available?surface=reader_chat | 返回可见候选、固定版本、selectable、blocked_reasons、相关模板 |
| 新任务预检（扩展原入口） | Skill/version、可信 entry_context、材料、执行方案；不调用模型 |

实现统一 resolver，供阅读、比较、审查、导读、前沿与调度复用。各功能不得再各自拼接固定菜单或只靠前端过滤。

客户端提供的 surface 仅是选择请求，不是授权证据。后端根据受信任的任务类型、关联会话、论文数量及专用任务绑定确定上下文；客户端改写 surface、skill_id 或调用其他路由不能绕过适配、资料和工具限制。通用任务接口也必须使用相同规则，防止只在可见菜单上做限制。

## 6. 可见性、兼容性与权限

| 层次 | 决定什么 | 不能替代什么 |
| --- | --- | --- |
| 可见性 | 哪些入口展示候选 | 不授予数据或工具权限 |
| 新任务可用范围 | 哪些类型能新建任务 | 不证明模型、材料或输出契约适配 |
| 技能版本兼容性 | 是否可进入对应适配器 | 不扩大工具白名单 |
| 执行授权 | 账号、会话、文件、MCP 子集、运行绑定 | 不因 UI 开关放宽 |

隐藏某入口仅影响后续发现与新建；既有会话仍显示它实际绑定的技能，可按原绑定延续并保留历史结果。续聊中新选 Skill 或扩展资料范围仍需经过对应入口和任务授权校验，不能借旧会话绕过。若需要停止既有任务继续使用，使用全局停用/撤销权限，而不是把可见性当作安全撤销。

每次执行仍校验技能启停、资料权限、连接状态及工具绑定。历史结果和 Run 快照不会因隐藏或停用而删除。已有技能 ZIP 的申报范围、角色提示和模板均不能修改这些规则。外部论文操作 Skill/API 仍使用独立 Bearer scopes，不与站内功能入口权限混为一谈。

## 7. 迁移与实施顺序

1. 注册稳定入口与适配器契约，新增 placement 存储、审计、并发修订及统一 resolver。
2. 给内置技能按真实职责配置默认范围：chat 用于研究/阅读对话，paper_read 用于阅读，paper_compare 用于比较，paper_review 用于审查，frontier_monitor 用于前沿，paper_guide 用于导读。默认值是显式迁移配置，不按技能名称自动推断。
3. 自定义技能保留既有会话和已关联模板；由实际适配检查给出迁移建议，在技能配置页确认新范围。没有明确兼容证据的专用任务不自动启用。
4. 先交付技能配置页与预览，再替换阅读对话选择器和真实版本绑定；模板仅作为所选技能的辅助要求。
5. 接入比较、审查与导读，再为前沿主题/定时任务增加版本化技能绑定；运行检查和错误提示统一。
6. 清理旧 QUICK 与重复任务入口，补齐文档和回归验证。若新增 Runner 传输字段或契约，再同步升级协议，不能先让页面假装已生效。

## 8. 验收标准

- 技能管理页配置范围并保存后，各功能菜单一致更新；不同账号互不影响，未知入口不默认开放。
- 同一技能可用于多个兼容入口；关闭某入口不改变其他入口、不删除历史会话。
- 阅读输入区展示真实技能，不混入假技能；选择本身不调用模型，发送后 Run 记录所选版本和哈希。
- 模板只改变要求，不能悄悄切换 Skill；兼容会话内可按轮次切换技能并保存真实版本，扩权和分支需要明确处理。
- 普通对话技能即使配置前沿/批注可见，也会因契约不兼容而禁用；后端直接请求同样被拒绝。
- 比较任务少于两篇、跨账号论文、失效文件、失配执行方案、旧配置修订均有明确拒绝结果。
- 前沿主题按绑定技能执行并保存证据与报告；手动与定时路径一致，不跳过去重或审批。
- 隐藏入口不错误撤销旧会话；全局停用、凭据与原有权限撤销仍有效，不能通过其他入口绕过。
- 升级默认版本后显示新兼容性，既有会话/Run 不静默换版；已有保存设置的内置技能不会在启动时被默认值覆盖。

## 9. 后台设计与显示名补充

Skill 需要支持后台直接创建、指令/资源编辑、草稿、试运行和不可变版本发布；复用现有 name 作为显示名语义，稳定 ID 不因改名变化。后台设计、自定义运行、逐轮切换和流式输出统一见 [产品化智能体工作台设计](AGENT-PRODUCT-DESIGN.md)。该设计更新了本文件早期的永久单 Skill 会话约束；现有实现尚未完成迁移。
