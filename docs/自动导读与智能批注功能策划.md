# 自动导读、重点标注与解释功能策划

日期：2026-11-19。状态：文本材料 MVP 已实现；下述后续能力以实现验收记录为准。

最新要求：仅用户触发。打开、导入、刷新、换标签均不自动调用 Skill。右侧输入框显示“试试：自动批注 / 阅读论文”，选择后可修改要求，再确认才执行。

实现方式已收敛为 Skill 结构化输出，具体以[《Skill 驱动导读批注接口设计》](Skill驱动导读批注接口设计.md)为准；该文明确字段契约、材料工具、既有批注投影及兼容接口。

## 1. 产品目标

用户打开一篇论文后，可以立即回答四个问题：

1. **这篇论文要解决什么，贡献是什么？**
2. **我应该按什么顺序阅读，先看哪里？**
3. **哪些句子、公式、图表和实验最重要，为什么？**
4. **这一处怎么理解，有什么前提、局限或需要核对的地方？**

功能名称建议为“自动导读”。它包括一份可恢复的论文导读、一个阅读路线和一层独立的 AI 批注。继续使用现有智能体与 Skills 完成内容理解，平台管理材料、任务、证据定位、版本、展示和缓存。

自动导读与交互精读衔接：导读帮助找到重点；需要理解重点时，可在原文旁展开已有解释，或进入 kelip 六站精读继续讨论。不会默认对每篇新论文执行完整精读。

## 2. 使用流程

```text
论文具备 PDF 全文
    ↓
首次进入阅读 → 检查当前版本是否已有导读
    ├─ 有：立即恢复导读与 AI 标记，不调用模型
    ├─ 已有任务：显示进度，不重复提交
    └─ 无：显示建议；用户选择并确认后调用 Skill
                ↓
       总结 + 阅读路线 + 少量重点与解释
                ↓
       平台核对原文、页码及定位
                ↓
       左侧导读卡片 ↔ 中间原文重点 ↔ 右侧追问
```

触发点为**用户选择“自动批注”并确认**。打开 PDF 仅恢复已有结果；选中建议和打开配置也不调用模型。后台生成不阻塞阅读。取消配置不创建任务，不启用首次打开或入库触发策略。

只有书目或摘要时，可以提供明确标为“摘要级”的临时概览，但不生成全文重点批注，不声称已分析方法和实验。管理页继续提供补充全文入口。

## 3. 阅读器界面

保持现有多论文标签、可调三栏及 PDF 栏上方工具栏。新增内容嵌入现有阅读器。

```text
论文标签 A | 论文标签 B | ＋
┌──────────────────┬──────────────────────────┬────────────────────┐
│ 导读 / 目录 / …   │ PDF 工具栏               │ 当前论文智能体会话 │
│                  ├──────────────────────────┤                    │
│ 一句话理解       │ 原文                     │ 追问这一段         │
│ 核心贡献与边界   │ 重点高亮 + 页边 AI 标记  │ 解释公式           │
│                  │                          │ 对照图表           │
│ 建议阅读路线     │ 点击标记展开：           │ 核对实验           │
│ ①问题与动机      │ 为什么重要 / 通俗解释   │                    │
│ ②核心方法与图    │ 原文证据 / 后续问题     │ 模板 + 图片 + 输入 │
│ ③关键实验与局限  │                          │                    │
│                  │                          │                    │
│ 重点列表         │ AI 批注可独立显示/隐藏  │                    │
│ 已读范围与缺口   │                          │                    │
└──────────────────┴──────────────────────────┴────────────────────┘
```

### 3.1 左侧“导读”页

在现有“目录、批注、高亮、译文、信息”前增加“导读”，包含：

- **论文速览**：一句话结论、研究问题、核心思路、主要贡献、结论适用范围。
- **建议阅读路线**：要看的章节、物理页、图表及阅读目的，每站可跳转原文。
- **重点清单**：按“问题与贡献、方法、公式与定义、图表、实验、局限”筛选，默认按阅读路线排序。
- **材料覆盖**：具体读过哪些页和章节，是否看过图、是否读取官方代码，哪些尚未分析。
- **操作**：显示/隐藏 AI 批注、重新生成、查看版本、导出导读；重新生成显式消耗一次任务。

导读状态必须可见：待生成、生成中、部分完成、已完成、失败、旧版。失败提供重试和删除入口，不出现无法移除的失败记录。

### 3.2 中间原文

重点以轻量高亮和页边 AI 标记呈现，不在默认状态为全文铺满长解释。每篇默认建议生成 **6–10 个重点**，作为产品配置初值，依据试运行质量调整。

点击重点，展示预先生成的解释卡片：

| 内容 | 用户获得什么 |
| --- | --- |
| 类型与阅读优先级 | 必看、建议看、按需展开；同时说明判断理由 |
| 原文 | 可核对的短引文或图表/公式的准确定位 |
| 为什么重要 | 与问题、方法或结论的关系，读这一处要掌握什么 |
| 通俗解释 | 用简洁语言解释，不复述整段摘要 |
| 前提与边界 | 适用条件、作者主张与实验证据的区别 |
| 建议追问 | 如“这个基线是否公平”“这里的假设何时失效” |
| 来源与覆盖 | 物理页、文件版本、证据类型及缺失信息 |

展开已经生成的解释、切页和显示/隐藏标记均不调用模型。“进一步解释”才创建新的有界任务，输入框预填问题和当前选区，允许修改后发送。

### 3.3 右侧会话

提供常用模板：

- 用一个具体例子解释这处重点。
- 逐项解释这个公式中的符号与假设。
- 这张图的输入输出和各模块是什么？
- 哪个实验直接支持这个结论？
- 按 kelip 六站带我继续阅读。

一次提交可携带原文选区、重点 ID、导读版本和用户上传的图片。图像理解只路由到已验证支持视觉的能力；没有视觉能力时只能解释实际读取的文本和图注，不宣称读懂了图像。

## 4. 重点如何判断

采用“与理解论文的关系”解释重要性，不以字体大小、出现频率、标题位置或模型打分直接代替判断。

| 重点类型 | 选取目标 | 解释应回答的问题 |
| --- | --- | --- |
| 问题与动机 | 任务定义、已有方法的关键不足 | 为什么要做，具体解决什么？ |
| 贡献 | 真正新增的技术、设定、证据 | 新在哪里，与哪些既有工作比较？ |
| 方法 | 决定整体思路的模块、流程与关键步骤 | 为什么这样设计，各部分如何连接？ |
| 定义与公式 | 理解方法所必需的概念、假设、目标 | 符号含义、约束条件及直观作用是什么？ |
| 图表 | 总览图、关键结果图及必要的示例 | 这张图帮助理解哪个关键问题？ |
| 实验 | 主要结论的直接证据与关键消融 | 比较条件是什么，证据支持到哪里？ |
| 局限 | 作者说明的局限与证据不足处 | 什么还没证明，什么时候可能不适用？ |

阅读路线允许因论文类型变化：方法论文重点看方法和消融；Benchmark 论文重点看构建、覆盖、评价与偏差；理论论文重点看定义、假设、定理和证明；综述重点看分类框架、纳入范围和证据缺口。没有训练过程的论文不强行生成“训练损失”重点。

“作者声称”“已看到的实验证据”“智能体的解释/推断”和“建议核对的问题”分别标识。不能把模型提出的问题写成论文已经存在的错误。

## 5. 自动批注与人工批注

### 5.1 独立图层

- 来源分为“我的批注”和“AI 导读”，可分别显示和隐藏。
- AI 标记带“AI”来源和类型标签；颜色仅辅助区分，不能只靠颜色传达信息。
- 复用现有四种批注颜色，暂定黄色为核心内容、蓝色为解释、绿色为证据、粉色为边界；不改变人工批注的已有配色含义。
- 用户可对 AI 批注采纳、编辑副本、隐藏、忽略或删除；原始 AI 产物保留来源与生成版本。
- “采纳为我的批注”生成可编辑副本，保留 `derived_from` 关联；后续重新生成 AI 导读不覆盖该副本。
- 删除/隐藏的同版 AI 重点不因刷新或后台重复同步重新出现。新导读版本可查看差异，由用户选择是否恢复隐藏项。

### 5.2 准确定位

模型输出**短引文、页码和证据块 ID**，平台依据当前 PDF 实际文本计算坐标；不接受模型凭空生成 PDF 矩形坐标。

定位规则：

1. 首先校验 `paper_id + file_version + physical_page + evidence_block_id`。
2. 在指定页的文本块中核对引文，必要时规范化断行、连字和空白；保留原始引文。
3. 唯一可靠匹配时生成坐标；双栏、多处重复、跨页和扫描文本分别处理。
4. 无法唯一定位时标“定位待确认”，保留导读卡片与页级跳转，不能强行贴到相似句子上。
5. 图表与公式使用提取器提供的真实区域或结构锚点；没有可靠区域时只跳至所在页。

PDF 物理页与正文印刷页分开记录。OCR 内容标明来源和不确定性；不把“无法抽取”解释成论文没有相关内容。

## 6. 智能体与 Skills 方案

### 6.1 自动导读：一个受限基础任务

新增 `paper_guide` 能力，由现有 Runner 执行：

- 输入论文身份、文件版本、论文类型、真实章节和文本块、生成范围、必要的已知偏好。
- 选择论文材料、归纳贡献、制定阅读路线和解释重点由 Agent 完成。
- 平台负责材料准备、访问范围、输出校验、坐标匹配、幂等、保存与显示。
- 输出一次同时包含速览、路线、重点与短解释，不为每个重点再发一次模型请求。
- 先读目录、摘要、引言和结论，再按预算选择关键方法与实验页；不足时输出部分导读，明确尚未覆盖的内容。

### 6.2 复用已有科研技能

| 任务 | 复用策略 |
| --- | --- |
| 低成本自动导读 | 复用现有论文阅读工具及 Nature 流程中的证据分级、粗筛与覆盖规范；增加适合本产品的结构化导读契约 |
| 交互精读 | 对接 `kelip-paper-reading` 的动机、架构、训练/推导、数据、信息流和具体例子，逐站接续 |
| 结构化研究卡 | 用户选择后运行 `nature-paper-card`，保留其完整结构，不把它缩减后冒称完整 Paper Card |
| 全文对照与翻译 | 独立使用 `nature-reader`，复用已有正文、图片和 source-map，避免重复提取 |
| 批量精读 | 独立任务使用 `paper-reading-batch`，不在自动导读默认执行范围内 |

服务器现有 Nature 背景发现适配不等于 kelip 材料脚本、视觉工具及 Nature 全文技能已经全部可用。这些能力须完成依赖、资源访问、模型和产物兼容验证后再开放。

### 6.3 文档显示

速览、解释和导读报告统一通过现有 **Marked + DOMPurify** 层显示。原始 Markdown 与结构化重点同时保存，导出使用原始 Markdown；不把不可信 HTML 存回论文信息。

Markdown 本身不能替代公式排版。复杂数学公式若需要可读排版，另行接入公式渲染层并验证安全与兼容；不能仅因 Marked 接入就宣称已支持数学公式。

## 7. 明确触发、缓存和费用

唯一执行入口是用户明确确认：

| 操作 | 行为 |
| --- | --- |
| 打开、刷新、切换论文 | 查询已有结果，不创建任务 |
| 点击“自动批注” | 展开技能、阅读目标、页数和重点数量配置，不调用模型 |
| 确认生成 | 调用现有 Runner 与所选兼容 Skill |
| 点击“阅读论文”并确认 | 创建绑定本论文的阅读会话，使用现有阅读 Skill |
| 相同配置再次确认 | 优先复用当前任务或结果；失败后允许明确重试 |

幂等/缓存键包括：`paper_id + file_version + guide_mode + skill_version + config_hash`。相同键同时打开多个标签、切换会话或浏览器刷新，只关联已有任务或结果。

- 通用导读属于论文资料，不绑定某一个讨论会话；同一 PDF 的多个阅读会话复用基础导读。
- 不同阅读目标通过路线筛选优先复用基础产物；确需重新分析时创建明确的新任务。
- 更新 PDF 后旧导读标“旧文件版本”，不继续叠加到新原文；新版本等待用户再次确认生成。
- 相同 PDF 仅更换显示标题不应触发全文重新分析；缓存键中的配置变化需区分显示信息与实质阅读目标。
- 导读失败保留已有可用版本，允许手动重试；不无限自动重试或每天重复生成。
- 用量、耗时、费用估算与覆盖范围记录在既有 Run 中。语义结果缓存和材料缓存分开，未知费用不显示为零。

## 8. 接口与数据模型

以下是拟新增设计，不表示当前服务已有这些接口。

### 8.1 接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/reader/papers/{id}/guide` | 当前文件版本的导读、覆盖、重点、状态及关联任务 |
| `POST /api/reader/papers/{id}/guide-runs` | 仅明确确认创建任务，带 confirmed、范围和幂等键 |
| `GET /api/reader/papers/{id}/guides` | 查看历史导读版本及文件版本 |
| `PATCH /api/reader/guide-items/{id}` | 隐藏、忽略、恢复；采用乐观版本校验 |
| `POST /api/reader/guide-items/{id}/adopt` | 幂等采纳为个人批注，保留来源 |
| `POST /api/reader/guide-items/{id}/explanations` | 对指定重点补充解释，显式创建新 Run |
| `POST /api/internal/reader/guide-runs/{id}/result` | 绑定当前 Run 的受限工具提交结构化结果 |

内部提交不能替用户采纳或覆盖人工批注；页面展示、导出和展开不调用模型。

### 8.2 数据结构

| 实体 | 主要内容 |
| --- | --- |
| `paper_guides` | 论文、文件版本、模式、技能及配置版本、Run、状态、速览 Markdown、路线、材料覆盖、发布时间 |
| `paper_guide_items` | 类型、阅读优先级、为什么重要、通俗解释、证据与推断标识、定位状态、显示状态、版本 |
| `paper_guide_evidence` | 原始文本块 ID、物理页、短引文、图表/公式锚点、平台核验后的坐标、材料类型 |
| `reader_annotations` 扩展 | `origin=user/ai_adopted`、`derived_from_guide_item_id`，或等价的关联表 |
| 阅读偏好 | 手动触发参数、导读模式、预算、是否显示 AI 图层、当前导读版本与展开状态 |

导读版本与任务状态分开：任务失败不删除上一份成功产物。候选重点先暂存，再校验证据和定位，最后发布可用版本；有部分未定位重点时显示具体缺口，不能以 Run 成功代替导读完整。

## 9. 与当前代码的对应关系

当前代码已具备：

- `app/reader/pages.py`：PDF 文件哈希、原始物理页文本、章节信息。
- `app/reader/schemas.py`：选区、归一化坐标、高亮和批注结构及校验。
- `app/reader/router.py`：批注读写、位置与译文接口。
- `frontend/src/reader/useReaderOrchestrator.ts`：页码跳转、批注刷新、选区到会话的编排。
- `frontend/src/components/reader/ReaderSidebar.vue`：目录、批注、高亮、译文、信息的现有入口。
- `frontend/src/shared/markdown.ts`：Marked 统一解析与安全展示。
- 现有 Agent Run：幂等执行、会话关联、状态、取消和用量保存。

缺口包括：结构化导读产物、明确触发与缓存、AI 批注图层、文本块到坐标的可靠定位、图表解释能力适配。

当前高亮接口要求真实引文和坐标，阅读位置 `tab` 枚举也未包含 `guide`。实施时同步扩展前后端协议与恢复逻辑；不能仅在左栏加按钮就认为功能完成。

## 10. 分阶段实施

### P0：先完成“拿到论文就知道怎么看”

- 增加导读页、状态、明确确认与一次性任务缓存。
- 一次轻量任务输出速览、阅读路线及 6–10 个候选重点与短解释。
- 每条重点有真实页码及短引文；支持跳页，可靠匹配的文本可自动标记。
- 与人工批注分层，支持隐藏、删除、失败重试和重复任务复用。
- 先使用固定样本验证完整链路，再做一次最小真实调用，校准实际成本和结果质量。

验收示例：打开一篇已有 PDF，看到研究问题、贡献、建议阅读的章节/页码，以及至少若干经核验的重点；点击能回到原文。刷新和重新打开不再次收费，删除的标记不复活。

### P1：原文内解释与可管理批注

- 页边标记和解释卡片，重点类型筛选、覆盖缺口提示。
- 采纳/编辑个人副本，查看新旧导读差异。
- 对选中重点继续追问，支持图片及图表解释的能力探测。
- 接入 kelip 六站交互阅读，保存站次、图文证据和会话进度。

### P2：面向个人研究目标的导读

- 按“快速判断价值、理解方法、检查实验、复现准备”等目标生成不同路线。
- 复用基础导读，仅补充新增问题，避免反复重读全文。
- 与领域追踪、论文比较和知识卡联动，用户选择后将导读发现整理为长期知识。

## 11. 验收重点

| 场景 | 标准 |

| 能否帮助开始阅读 | 有明确的问题、贡献、路线和阅读目的，不能只生成泛化摘要 |
| 重点质量 | 覆盖论文真正关键的问题、方法与证据，解释为什么重要，避免满篇高亮 |
| 来源准确 | 引文存在于指定版本和页面，坐标经平台核验；匹配不确定时不强行标注 |
| 内容边界 | 摘要、全文、图像和代码阅读范围分别说明；未读不写成已验证 |
| 明确触发与复用 | 同版本同配置只执行一次，多标签和刷新复用；已有批次不重复收费 |
| 版本变更 | 新 PDF 不显示旧坐标，个人批注不被 AI 重新生成覆盖 |
| 交互 | 点击重点跳原文，展开缓存解释不调用模型，进一步解释能继续原关联上下文 |
| 可管理性 | AI 图层独立开关，采纳幂等，隐藏/删除可管理，失败项可以移除和重试 |
| 性能与用量 | PDF 不被后台任务阻塞，每轮有范围与预算，任务失败无无限重试 |
| 阅读回归 | 多标签、可调三栏、工具栏位置、图片上传、回车发送与人工批注正常 |

文本导读与批注实现情况见《Skill导读与批注实现验收》。图像、OCR、代码分析和完整六站精读仍为后续能力。
