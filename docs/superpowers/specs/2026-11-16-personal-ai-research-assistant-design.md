# 个人 AI 科研助手平台 — 设计文档

日期：2026-11-16
状态：待用户审批

## 一、意图与背景

在一台自有 Linux 服务器（Ubuntu 24.04，AMD Ryzen 9 8945HX 32 线程，30GB 内存，241GB 可用磁盘，无 GPU）上部署一套 7×24 无人值守的"个人 AI 科研助手"，服务一位科研用户（默认研究领域：具身智能，VLA / Diffusion Policy / Flow Matching）。

为什么自研而不是改造开源项目：两轮深度调研（2026-11-16）确认——用户点名的 Amadeus 已停更且无 LICENSE、research-agent 无真实匹配项目、PaperFlow 缺精读层、Open Paper 为 AGPL + 9 服务重架构且强绑三家官方 API；社区内（DeerFlow/SurfSense/Khoj/RAGFlow/PaperQA2 等）也没有任何项目同时覆盖四大功能。改造多个异构代码库的长期维护成本高于一套自洽轻量系统，且用户的首要约束是"长期无人值守、低维护复杂度、可扩展（未来加实验管理/多 Agent 协作）"。

## 二、目标 / 非目标 / 反目标

**目标**
1. 四大模块端到端可用：前沿雷达、论文精读、AI 导师、长期记忆（共享知识库）。
2. 统一 Web 工作台，电脑与手机浏览器可用，自然语言交互。
3. LLM 全走外部 API（OpenAI-compatible 为主，兼容 Anthropic-compatible），多提供商可配置、分档路由。
4. 每日定时采集 → 筛选 → 日报 → 钉钉群机器人推送；每周趋势报告。
5. 本地持久化（SQLite + Qdrant），支持备份、迁移、导出。
6. Docker Compose 一键部署，停机重启后自动恢复。

**非目标（本期不做）**
- 本地部署大模型（无 GPU 也不需要）。
- 公网暴露与 HTTPS/强认证（用户明确后置；本期 Web 只绑本机/内网）。
- Zotero 双向同步、实验管理、代码复现、多 Agent 协作（留作扩展点，架构上留接口即可）。
- 多用户/权限体系（单人使用）。

**反目标（出现即算失败）**
- 推荐已推过/已读过的论文（重复打扰）。
- 答案中的引用与论文原文对不上（引用必须可溯源到 PDF 片段）。
- 需要用户手动重启才能恢复的定时任务。
- 依赖任何已到期/不可用的单一 API 提供商才能启动。

## 三、已定决策（用户拍板或调研后由设计者定，标注 ✋=用户已确认 / 🔧=设计者决定）

- ✋ 推送通道：钉钉群机器人 Webhook（access_token + 加签 secret）。
- ✋ LLM 提供商：内部网关 `https://llm.inner.bza.edu.cn/plan`（可用，glm-5.3 / glm-5.3-flash / deepseek-latest / doubao）+ DeepSeek 官方 `https://api.deepseek.com`（可用）。GLM 官方 bigmodel 套餐已到期，保留配置项不启用。
- ✋ 研究领域默认配置：具身智能（cs.RO / cs.AI / cs.LG 相关 arXiv 分类 + 关键词）。
- ✋ 公网访问后置，本期 Web 绑定 localhost/内网（本机已启用 Tailscale，绑定其 IP 100.64.0.7，手机经 Tailscale 访问，不额外暴露校园网）。
- ✋ 允许安装 Docker Compose + 国内镜像加速，调整服务器为合盖不休眠、开机自启（用户将以 `sudo -v` 授权，安装由实现者完成）。
- ✋ 雷达规模：采集 → 低成本预筛（关键词+向量）→ LLM 精筛 → 每日日报最多 10 篇，按相关性排序。
- ✋ 存量导入：支持 PDF 文件夹批量导入作为初始记忆（自动元数据补全 + 去重），P1 实现。
- ✋ 知识地图：Web 可视化概念节点图（节点/边），掌握度由对话自动推断 + 用户可手动修正，学习计划为按周任务清单。
- 🔧 整体形态：自研轻量单体应用 + 复用成熟组件库，不做多项目拼装。
- 🔧 技术栈：Python 3.12 + FastAPI；前端为构建产物由 FastAPI 静态托管（具体框架由实现者定，必须响应式适配手机）；SQLite（业务数据，WAL 模式）+ Qdrant（向量，单容器）；本地 CPU embedding（sentence-transformers + BGE，型号由实现者在 bge-small-zh-v1.5 / bge-m3 中按内存与效果权衡）；APScheduler 进程内定时任务（CronTrigger，错过触发自动补跑）。
- 🔧 LLM 网关：自研薄适配层，两类协议（OpenAI-compatible chat/completions；Anthropic-compatible messages），统一处理多块 content（thinking 块 + text 块，实测所有目标模型都返回 thinking 块）。分两档：`fast` 与 `strong`，每档可独立配 base_url/model/key，支持多提供商故障转移（按顺序重试下一个）。默认路由：`fast`（每日批量：筛选/摘要/日报）→ **DeepSeek 官方**（独立配额，避免内部网关额度与日常 Claude Code 使用冲突）；`strong`（精读/导师/对比）→ **内部网关 glm-5.3**。网关具体契约（SSE、usage 字段、thinking 字段名、上下文上限）在 P1 实现时实测确定。隐私注记：内部网关为用户所属机构的服务，论文全文与对话可经其传输；如需更保守策略可改 fast 路由。
- 🔧 Embedding 不依赖外部 API（DeepSeek 无 embedding；GLM 套餐到期），本地 BGE CPU 推理，个人规模（万级 chunk）延迟可接受。
- 🔧 精读引擎：自研章节切分 + 检索问答，借鉴 PaperQA2（Apache-2.0，仅借鉴设计，可引为依赖）与 Open Paper 的引用溯源 UX；公式解释基于 PDF 文本抽取 + 上下文，不做 OCR 公式识别（后置）。

## 四、系统架构与数据流

```
手机/电脑浏览器 ──Web 工作台（FastAPI 托管 SPA）
                    │
        ┌───────────┼────────────┐
   前沿雷达      论文精读      AI 导师
        └───────────┼────────────┘
                    │
        共享记忆层：SQLite（论文/笔记/对话/兴趣/去重）
                    Qdrant（全文 chunk 向量）
                    │
        LLM 网关（fast/strong 分档，多提供商故障转移）
        Embedding（本地 BGE）
                    │
        调度器（APScheduler）：每日 arXiv 采集、周报、备份
                    │
        钉钉群机器人（Webhook + 加签）
```

**数据流（前沿雷达，每日 08:00）**：arXiv API（具身智能相关分类，近 24h/48h 新论文）→ 元数据入库 + 指纹去重（arXiv ID / 标题向量相似度双保险）→ `fast` 档 LLM 逐篇筛选（相关性打分 + 一句话理由）→ 相关论文生成中文日报 → 钉钉推送 + Web 端存档 → 用户"感兴趣/不感兴趣"反馈写回兴趣画像。

**数据流（论文精读）**：上传 PDF 或给 arXiv 链接 → 下载 + PyMuPDF 解析 → 章节切分 + chunk + 本地 embedding 入 Qdrant → 用户点"深度解读"→ LLM 按章节生成解读（背景/创新/架构/公式/实验/局限）存为笔记 → 用户可就原文提问（向量检索 + 引用页码/原文片段溯源）→ 多篇对比生成对比矩阵。

**数据流（AI 导师）**：对话 → 检索记忆库（已读论文、已有笔记、知识地图）作为上下文 → `strong` 档回答 → 学习计划与知识地图按对话进展更新。

**数据流（长期记忆）**：所有模块的产物（论文元数据、笔记、对话摘要、反馈）统一入库；兴趣画像 = 反馈标签 + 向量化的已读论文中心；"已推送/已读/不感兴趣"三态去重。

## 五、数据模型（SQLite 主要表）

- `papers`：arXiv ID/标题/作者/摘要/分类/来源/状态（new→pushed→reading→read/dismissed）/PDF 路径/时间戳
- `chunks`（映射到 Qdrant collection）：paper_id、章节、页码、文本、向量
- `notes`：paper_id、类型（章节解读/批注/对话摘要）、内容、时间
- `conversations`：模块、标题、消息 JSON
- `interest_profile`：关键词权重、反例关键词、更新时间
- `push_log`：paper_id、日期、渠道、是否已读
- `reading_plan` / `knowledge_map`：导师模块的结构化产物（概念节点/边 + 掌握度 JSON，掌握度由对话自动推断，允许用户手动修正）
- `llm_usage`：时间、提供商、模型、档位、tokens（成本追踪）

## 六、Docker Compose 拓扑

服务：
1. `app`（自研主应用，FastAPI + APScheduler + 前端静态文件，挂载 `./data`）
2. `qdrant`（官方镜像，挂载 `./data/qdrant`）
3. `backup`（轻量定时备份容器：每日导出 SQLite + Qdrant snapshot 到 `./backups`，保留 N 份）

`.env` 存放所有 API key（钉钉 access_token/secret、各 LLM 提供商 key），不入库不入镜像。导出功能：笔记/论文库导出为 Markdown + JSON 归档。

资源预算：app ≤ 4GB（含 BGE 模型），Qdrant ≤ 2GB，系统余量充足。

## 七、分阶段实施与验收标准

**P1 骨架 + LLM 网关 + 论文库（含批量导入）**：安装 Docker 与镜像加速、调整服务器电源策略（合盖不休眠/开机自启）；Compose 起服务；Web 可访问；能上传 PDF/arXiv 链接并完成解析入库 + 向量化；**支持 PDF 文件夹批量导入（异步任务 + 进度展示 + 自动元数据补全 + 去重）**；LLM 网关对两个可用提供商均实测通过（含 thinking 块解析）；`llm_usage` 记账。
验收：上传一篇具身智能论文 PDF → 3 分钟内可检索问答，答案带原文页码引用；批量导入一个含多篇 PDF 的文件夹，进度可见、无重复入库。

**P2 论文精读**：章节级解读生成、原文溯源问答、多篇对比矩阵、笔记保存。
验收：任选一篇新论文生成六维解读（背景/创新/架构/公式/实验/局限）；对"VLA、Diffusion Policy 和 Flow Matching 有什么区别"类问题给出结合已读论文的结构化讲解。

**P3 前沿雷达 + 钉钉推送**：每日定时采集/预筛/精筛/日报/推送（Top 10）；反馈写回画像；去重生效。
验收：连续 3 天无人值守，每天 08:00±10min 收到钉钉日报，无重复论文；用户标记"不感兴趣"的方向次日报文数量下降。

**P4 AI 导师 + 记忆完善 + 周报**：知识地图（概念节点图可视化 + 掌握度自动推断/手动修正）、按周学习计划；每周五周报（领域进展/已掌握/未解决/下周建议）推送；数据导出与备份演练。
验收：模拟恢复演练（删除 data 目录 → 从备份恢复 → 论文库与笔记完整）；周报正常送达；知识地图在 Web 端可见且随对话更新。

每阶段结束运行自动化冒烟测试（pytest + 关键路径脚本）并演示给用户。

## 八、风险与对策

- 内部网关不稳定 → DeepSeek 官方作故障转移，网关健康检查自动切换。
- 本地 embedding 在服务器无 GPU 时首次下载/推理慢 → 预下载模型进镜像或启动时缓存，bge-small 量级 CPU 可接受。
- arXiv API 限流 → 指数退避 + 失败次日补采。
- 公式/数字幻觉 → 引用必须带原文片段，答案附溯源 UI；关键数字标注来源页码。
- 磁盘增长（PDF + 向量）→ 每日备份保留策略 + 磁盘水位告警推送钉钉。
- Docker Hub 与 HuggingFace 直连不通 → 配置镜像加速站拉取镜像与模型，实现者负责处理。

## 九、实现者拍板项备忘（设计者决定，用户可否决）

- **去重口径**：打开精读或手动标记 = 已读；"已推送"论文不重推（arXiv 新版本视为关联更新，在日报中以"更新"标注而非新条目）；"不感兴趣"= 降权而非硬过滤（避免信息茧房）；跨来源（arXiv 抓取 vs 上传 PDF）按标题向量相似度自动判重，高相似自动合并并在 UI 提示。
- **备份**：本期仅同盘 `./backups`（每日一次，保留 14 份），预留 rclone 异地推送配置位；异地备份待用户指定目标后启用。
- **API keys**：从用户现有 cc-switch 配置库提取写入 `.env`（用户已确认模型配置来源），不入 git。
- **日报内容**：每篇含中文一句话摘要 + 相关性理由 + 与兴趣画像的关联；日报尾部附"今日未入选但可能值得关注"3 篇。
