# 后续计划

更新：2026-11-22。以 [当前状态](STATUS.md) 和 [架构](架构.md) 为基线，只列尚未完成事项。优先级是实施建议，不代表已交付或已排期。

本次历史需求对照与建议分批顺序见 [项目总览](PROJECT-AUDIT.md)。以下按技术领域保留待办，不把已经交付的首页、标签、回收站、手动 Zotero 和个人连接重新列为重建项。

## P0：状态可信与文档基线

- 修正用户资料 `capabilities.auth=False` 与实际认证机制的冲突；设置页应分别呈现认证/账号隔离能力和当前仅管理员开放策略。验收不改变登录范围或注册策略。
- 部署版本用 Git 提交及协议/迁移判断，避免 `0.1.0` 或历史测试数字误导；真实能力验证与配置声明分开记录。

## P0：执行配置与可检查会话

当前已有个人连接、加密凭据、模型/能力声明、角色补充提示、可配置额度、会话绑定和基础诊断。下一步：

| 事项 | 实现方向 | 验收标准 |
| --- | --- | --- |
| 模型能力与目录 | 单连接多模型目录、声明/实测分离、明确确认的最小真实探测 | 预检不收费；真实探测显示目标和额度；视觉/长上下文缺口可解释 |
| 独立角色与执行方案 | Role/Profile 组合连接、模型、Skill、工具与预算，固定修订 | Web 有可编辑表单、有效配置预览；账号不串用；默认变更不改旧会话 |
| Skills/MCP 管理扩展 | 复用现有注册表与 13 个内置工具；外部服务发现、逐项授权、凭据隔离 | 安装/发现不自动授权；内置材料边界保留；变更可审计 |
| 会话检查器 | 独立 Run 页面、阶段诊断、事件回放、脱敏调试包、受控分支 | 分支和迁移明确确认，不向新服务商暗中发送旧内容；导出不包含 Key |
| 配置生命周期 | 连接分类/归档、历史版本策略、凭据轮换与撤销 | 旧任务可追溯；撤销即时生效；不会回退其他凭据 |
| 可解释用量 | 可靠请求级/累计 token 观测、费用来源与账本、主动追加额度入口 | 未知费用不为零；预算层级清楚；没有隐式付费重跑 |

- Runner 模板路径、legacy 模型覆盖和内部回调地址配置化，避免新机器照抄现有实例参数。
- 在独立服务完成整套备份恢复演练，核对身份、Key 解密、PDF、Skills、会话、附件、报告与向量；不影响生产。

## P1：Zotero 研究成果回流

手动双向书目/PDF、分类树、重复复用和恢复已完成最小实测。后续按收益顺序推进：

1. 用户确认后将导读/比较成果输出为 Zotero 子笔记，包含 PDF 哈希、页码、Skill/Run 与 Firework 回链；重复更新同一成果，不无限新增。
2. 只监听用户选定分类，接收既有 Connector 保存的条目，先展示候选再批准；支持暂停、恢复、事件去重，不接管官方 Connector。
3. 需求明确后再做原生批注与阅读状态适配，先单向再双向；校验文件哈希、坐标、类型、删除与冲突，禁止不同版本错误叠加。

保留 Zotero 的采集、引用和成熟书目能力，避免重复建设 CSL 引擎、完整 Translator 生态和云同步协议。以重复率、恢复率、整理时间及维护成本评估投入。

## P2：统一知识与规模化

- 从已确认批注、导读、报告和会话提取候选知识，采用审核、发布、更新/撤销流程，保留文件版本、页码、来源、Run 和 Skill。跨任务召回可追溯，区分原文、推测和个人观点。
- 在独立验证后考虑普通账号开放、共享库和协作角色；现有账号启停不自动开放登录。
- 多副本前先外置队列、并发锁和调度协调；不直接复制当前单 worker 服务。
- 站外消息与推送需单独授权，启用追踪不等于允许向外部账号发送研究资料。

每批沿用：明确范围 → 接口/迁移 → 隔离验证 → 备份与发布 → 不调用模型的检查 → 必要且明确触发的最小真实验证 → 文档与 Git。当前产品和未来设计分开维护，旧细节通过 Git 历史追溯。
