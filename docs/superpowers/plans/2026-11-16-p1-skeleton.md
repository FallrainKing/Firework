# P1 骨架 + LLM 网关 + 论文库 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在自有服务器上以 Docker Compose 跑起科研助手骨架：Web 可访问、LLM 网关双提供商可用、PDF/arXiv 论文入库并向量化（单篇+批量）、带页码引用的问答可用。

**Architecture:** FastAPI 单体应用（同时托管前端静态文件与 API）+ SQLite(WAL) 业务库 + Qdrant 向量库 + 本地 BGE-m3 embedding（CPU）+ 进程内 APScheduler 框架位。LLM 网关按 `fast`/`strong` 两档路由到可配置提供商，故障转移按序重试。

**Tech Stack:** Python 3.12, FastAPI, uvicorn, sqlite3, qdrant-client, sentence-transformers (torch CPU), PyMuPDF, httpx, APScheduler, pytest；前端为免构建原生 JS SPA；Docker Compose（app + qdrant + backup）。

**Spec:** `/home/f/research-assistant/docs/superpowers/specs/2026-11-16-personal-ai-research-assistant-design.md`

## Global Constraints

- Python 3.12；torch 仅装 CPU 版：`--index-url https://download.pytorch.org/whl/cpu`。
- embedding 模型固定 `BAAI/bge-m3`（1024 维），HF 下载走镜像：`HF_ENDPOINT=https://hf-mirror.com`。
- 所有密钥只存 `.env`（不入 git）；仓库根目录 `.gitignore` 必须含 `.env`、`data/`、`backups/`。
- 服务端口 8600；compose 发布绑定 `127.0.0.1:8600` 和 Tailscale IP `100.64.0.7:8600`，不暴露公网接口。
- LLM 响应可能含 thinking 块（content 首块 `type=="thinking"`），所有协议适配必须解析出 text 块。
- 每个任务完成即 `git commit`（消息格式 `feat|chore|test: ...`）。
- 测试命令统一在仓库根 `/home/f/research-assistant` 下运行 `pytest`。

## Review Focus

1. **thinking 块吞掉正文**：网关必须返回 text 块内容而非空串（实测 glm-5.3/deepseek 均带 thinking 首块）。→ Task 4 测试 `test_thinking_block_returns_text`。
2. **中文问题查英文论文**：跨语言检索必须命中（bge-m3 多语向量）。→ Task 5 测试 `test_cross_language_search`。
3. **批量导入单文件损坏不拖垮整批**：坏 PDF 记失败继续其余文件。→ Task 8 测试 `test_batch_skips_bad_file`。
4. **重复论文双源判重**：同一论文 arXiv 抓取与本地上传（标题近似）须合并不重复入库。→ Task 7 测试 `test_dedup_same_title_different_source`。
5. **Qdrant 未就绪时应用启动不崩**：向量库连接失败应重试退避，API 返回明确错误而非 500。→ Task 5 测试 `test_unreachable_qdrant_raises_clean_error`。
