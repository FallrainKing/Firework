关键差距：

1. 阅读时全局导航默认收起，其中的取消按钮也随之隐藏；右侧聊天没有直接停止入口。
2. 模板、原文、图片已有，但未形成统一上下文输入组件，缺少粘贴、拖放与论文提及菜单。
3. 历史会话入口与论文入口分离，长对话分页与滚动反馈不足。
4. Skill 在 Web 与 Runner 中静态注册，仅上传 ZIP 或解压到目录不会完成动态扩展。
5. 用户资料、设置和技能管理缺少统一入口。

### 1.4 统一设计原则

- 平台管理材料、会话、技能与运行状态，智能处理继续由现有智能体承担。
- 沿用 Vue 3、TypeScript、Pinia、FastAPI、SQLite、现有 PDF 引擎和私有 Runner。
- 复用既有任务、附件、草稿、SSE 和取消机制，不重复建设生命周期。
- 原文引用可追溯到论文、物理页与文件版本；标签关闭不删除研究记录。
- 上传、安装检查、分类、预览、切换布局均不调用模型；执行验证采用最小请求。
- 任务默认由用户明确发送，不因自动排队或隐藏操作产生新增模型调用。
- 当前按单用户设计；用户标识不等于已实现多用户账号与权限隔离。

### 2.2 F01：信息架构、用户标识与设置

#### 顶部保持四个研究模块

- 读论文：起始工作台与三栏阅读。
- 论文比较：比较任务及其关联论文。
- 定时任务：监控与周期执行。
- 论文库管理：分类、元数据、全文和会话管理。

技能库作为管理能力，从用户菜单进入；首页模板区和新建任务窗口提供“管理技能”快捷入口，不占据第五个研究模块。

#### 用户标识采用左上角方案

在品牌区旁显示小头像、用户显示名及下拉箭头。窄屏保留头像，显示名按空间隐藏。使用普通页面菜单，不在右下角放浮动控件，避免占用智能体输入框。

菜单结构：

| 菜单 | 内容 |
|---|---|
| 用户信息 | 显示名、头像、当前身份模式 |
| 技能库 | 管理技能、分类、版本和导入记录 |
| 设置 | 阅读与外观、智能体默认行为、用量护栏、数据管理 |
| 帮助与运行信息 | 快捷键、连接状态、版本与诊断信息 |
| 退出 | 只有实际认证系统支持注销时才显示 |

当前是单用户部署。MVP 的用户标识代表真实配置中的本地用户，不将宿主机操作系统账号当作产品账号，也不假装已实现多用户登录。沿用已有访问认证；没有注销接口时不提供无效退出按钮。

#### 设置的职责

| 分区 | 可设置项 | 规则 |
|---|---|---|
| 个人资料 | 显示名、头像 | 使用用户配置；不展示凭据 |
| 外观与阅读 | 主题、字体大小、默认三栏预设、默认辅助标签 | 用户默认值只用于新工作区；已有工作区保存值优先，显式“应用到当前工作区”才覆盖 |
| 智能体 | 默认任务技能、默认模板、能力与连接状态 | 模型来自服务器配置；不在浏览器保存模型密钥 |
| 用量 | 默认预算档位、执行前提示规则 | 不能超过服务端上限；费用估算与实际账单区分 |
| 技能管理 | 默认分类、上传限制说明、启用策略 | 上传限制由服务端控制，普通偏好不能绕过 |
| 数据 | 会话/笔记导出、备份信息 | 展示真实可用能力；没有恢复流程时不提供误导性恢复按钮 |

### 2.3 F02：阅读与会话导航

左侧增加“论文 / 会话”切换、搜索及“最近 / 固定 / 运行中”筛选。论文展开后显示关联任务，例如“方法精读”“实验审查”。主项点击打开 PDF，任务子项打开同一论文并恢复对应会话。管理菜单复用已有重命名、固定、归档接口，减少跳往管理页。

验收：一篇论文可找到多个历史任务；不重复建会话；切换不触发模型调用；归档任务可从专门入口找回。

### 2.4 F03：统一研究输入框

把模板、原文选区、引用论文、图片统一成可移除的上下文条。输入 / 显示模板，先填入要求再编辑；输入 @ 检索库中论文或已授权材料，不开放任意服务器文件。图片支持按钮选择、拖入和粘贴截图，复用统一的格式、数量、大小校验与归属检查。运行时允许编辑下一条草稿，但默认由用户再次发送。

验收：三种图片入口使用同一限制；显示上传中/失败/重试；来源页码和论文明确；切换标签保留草稿；选择模板、附件不调用模型。

补充规则：上下文条应区分当前论文、其他被引用论文、原文选段和图片。视觉能力来源于实际智能体/模型；图片上传成功不代表模型支持理解图片。一次发送需要按统一契约把上下文真正传给后端，不能只在界面显示标签。

### 2.5 F04：运行控制、消息与长对话

右侧当前运行显示“排队 / 执行 / 完成 / 失败 / 已取消”，标明真实工具活动、已用时和停止按钮；顶部保留运行任务数量入口，脱离左侧导航的展开状态。任务完成后允许从通知跳回对应论文和会话。错误和取消均保留原输入供编辑。

验收：全局导航收起仍可停止当前运行；切换论文不会丢失任务状态；断线不等于任务失败；不展示推测的完成百分比。

用户要求与助手回答分开展示；原文引用可折叠并定位，连续工具调用分组折叠。增加复制回答、展开来源、查看执行详情。只有用户位于底部才跟随更新；向上阅读时显示“新内容，回到底部”。添加历史分页，恢复可见消息位置。

验收：上翻不会被终态更新拉回底部；长回答、表格、公式、图片不撑破右栏；历史按需加载且无重复。

运行期间允许编辑下一条草稿；默认不自动发送。刷新或恢复页面不重放已经提交的运行，重试由用户显式触发并使用既有幂等机制。

### 2.6 F05：多论文标签、布局与移动端

保留现有标签和三栏，增加未发送草稿点、运行标记、失败标记、完整标题提示和标签溢出列表。增加阅读优先、讨论优先、恢复默认三种布局；桌面预设改变宽度，移动端使用原文/辅助/会话切换，更多操作进入抽屉。拖动即时更新画面，结束再统一保存，避免频繁保存请求。

验收：窄屏无横向页面溢出；长标题不挤掉关闭和加号；收起状态、宽度仍可恢复；打开/关闭标签不删除研究数据。

### 2.7 F06：会话头部、详情与用量

头部常驻当前论文、会话名、任务类型与运行状态；高级信息放“详情”，包括平台会话、原生会话、模型、运行记录和附件。展示本轮 tokens 与已记录的会话累计。费用明确标为 CLI 估算，不视为网关实际账单；记录的累计 tokens 不视为准确上下文窗口占用。支持视觉等能力应以服务端真实配置/验证为依据。

验收：缺失用量显示未提供；不计算虚假的剩余额度或上下文百分比；UI 不存模型密钥，不静默切换到其他模型。

### 2.8 F07：技能库与分类管理

#### 页面组织

技能库包含固定工具栏、左侧分类、中央技能列表、详情抽屉。

```text
研知  [头像 当前用户 ▾]      读论文  论文比较  定时任务  论文库管理

技能库                 搜索技能…   状态 ▾   来源 ▾   [上传技能 ZIP]
全部技能
阅读与理解             [技能名称] [版本] [已启用 / 未启用 / 不兼容]
实验与方法             用途简介 · 可用工具 · 任务类型
审查与比较             分类 / 标签 · 最近使用
检索与监控             [新建任务] [详情] [更多]
自定义分类 ＋
未分类

详情：说明 | 模板 | 文件 | 工具与预算 | 版本 | 使用记录
```

分类区、技能卡片和用户资料属于三种不同对象，不复用论文分类表或会话分类表。分类删除只解除技能归类，不能级联删除技能。

#### 技能卡片字段

- 名称、简介、图标、来源（内置 / 用户上传）。
- 当前默认版本和状态。
- 分类、标签、适用任务类型。
- 需要的输入：单篇论文、多篇论文、选中原文、图片等。
- 可用工具和是否需要视觉能力。
- 最近使用时间、关联会话数量。
- 主操作“新建任务”；更多菜单包含启停、改分类、上传新版本、查看记录、归档。

“支持图片”同时受技能声明和现有智能体实际视觉能力约束。技能声明不作为能力证明。

#### 分类规则

- 初始分类：阅读理解、方法实验、审查比较、检索监控、写作整理、未分类。
- 支持新建、改名、排序；同一技能可属于多个分类，并可有多个标签。
- MVP 分类为平级；如果将来支持子分类，再加入防循环和层级限制。
- 技能分类仅用于管理与筛选，不改变其工具权限和执行行为。

### 2.9 F08：ZIP 上传、安装和启用

```mermaid
flowchart LR
    Upload[上传 ZIP] --> Stage[隔离暂存]
    Stage --> Check[检查归档与技能结构]
    Check --> Preview[预览说明、文件、工具与预算]
    Preview --> Configure[补全名称、分类与执行档位]
    Configure --> Install[安装不可变版本]
    Install --> Disabled[已安装、未启用]
    Disabled --> Enable[用户启用]
    Enable --> Ready[新任务可选择]
    Check --> Rejected[失败原因与修复建议]
```

#### 上传交互

1. 拖入或选择 ZIP，显示大小和上传进度。
2. 展示识别到的技能名称、入口、文件数量及结构。
3. 工具、能力和预算要求以差异清单展示，不静默接受。
4. 缺少分类、展示名或平台配置时，在预览页补充。
5. 安装后默认未启用；启用完成才进入新建任务的可选列表。
6. 提供“结构检查”和可选“最小执行验证”，分别说明是否调用模型。

MVP 一包一个技能。ZIP 顶层可以直接有 SKILL.md，也可以有一个包含 SKILL.md 的单层包目录；多个候选入口时要求用户修正包，避免猜测安装目标。以后再支持明确的多技能批量导入。

用户看到的完整状态是“上传 → 检查 → 预览/补全 → 安装未启用 → 启用 → 新任务可选”。检查失败保留报告和修复建议；重复导入复用已有结果；只完成文件上传不能视为功能交付。

### 2.10 技能、模板、会话与运行的关系

| 对象 | 含义 | 示例 |
|---|---|---|
| Skill | 执行方法、资源、所需工具和输入要求 | 方法与实验审查 |
| 任务模板 | 预填给用户编辑的要求 | 只检查消融实验与结论支持 |
| 会话 | 某次研究目标及其持续上下文 | 对某篇论文的实验审查 |
| Run | 会话内一次实际执行 | 用户点击发送的一轮 |

一个技能版本可以提供多个模板。创建任务窗口先选择任务类型、论文和技能，再展示兼容模板；每个分类选择器支持选择已有分类或新建分类。

阅读输入框的 / 菜单区分：

1. “当前会话模板”：只填入要求，不改变当前 Skill。
2. “其他技能”：展示名称和用途，选择后进入新任务确认页，不在原生会话中静默切换技能。

PDF 必需技能在创建前检查全文；只有书目信息时引导补充。多论文比较检查论文数量；视觉必需技能在能力不足时不可发送并给出明确原因。

MVP 每个任务使用一个主 Skill。不在此阶段自动组合多技能或构建复杂工作流。

### 2.11 F09：论文库的密度与操作层级

沿用“预览图 + 标题 + 作者单位 + 简介”。搜索/分类区固定，增加卡片/紧凑列表切换、阅读状态筛选；卡片主操作为打开原文，管理信息、审查等进入更多菜单。未选中论文时不展示占空间的批量操作条，选择后展示对比与分类操作。缺全文保留醒目标识和定向导入入口。

验收：主要内容位于首屏；长标题/作者有完整信息入口；图片失败显示占位；缺全文状态不伪装成可阅读全文。新增阅读状态筛选需要先明确后端状态含义，不将导入 ready 当成已读。

说明：这是结合论文产品的适配建议，不是参考项目已实现的论文管理能力。

### 2.12 F10：统一反馈与成果导出

所有列表和弹层使用统一的载入、空内容、错误重试、保存中、已保存和保存失败样式。聊天成果可导出 Markdown，保留论文标识、会话信息、物理页和文件版本锚点。后续再接“保存为知识条目”，避免把聊天导出等同于长期记忆。

验收：网络失败不被显示为空列表；保存失败不显示成功；导出仍能追溯原文。

### 2.13 F11：高级扩展及范围边界

真实流式增量回答、会话分支、多智能体选择、语音输入、知识卡片、技能组合、共享技能市场与受控脚本执行列入 P2。

- 增量回答需要 Runner 输出增量、API 转发与客户端合并；现有 progress/SSE 不等于逐 token 输出。
- 会话分支需要原生智能体和服务端支持；复制聊天记录不等于独立的原生会话。
- ZIP MVP 支持指令、参考材料、模板和已有受限工具，不自动运行 scripts、安装依赖、启动服务或注册任意外部工具。
- 缺少必需工具的技能可保留为不可用版本，并明确原因，不虚构功能已生效。
- “导出聊天”与“长期知识记忆”分别设计；本阶段不以导出代替知识系统。
- 终端、Git、服务器文件编辑和开发权限模式不进入默认论文阅读界面。

## 三、实现规划

### 3.1 总体架构与职责划分

```mermaid
flowchart TB
    UI[技能库 / 新建任务 / 阅读会话] --> SkillsAPI[Skills Router]
    SkillsAPI --> SkillsService[安装、版本、分类与启停服务]
    SkillsService --> DB[(SQLite 技能注册表)]
    SkillsService --> Store[共享 data/skills 不可变资源]
    UI --> Session[Sessions / Agent Service]
    Session --> Registry[Skill Registry 解析可用版本与策略]
    Registry --> DB
    Session --> Snapshot[固定版本与执行策略快照]
    Snapshot --> Runner[现有私有 Runner]
    Runner --> Verify[核对版本、摘要和执行边界]
    Verify --> Agent[现有 Claude CLI]
    Agent --> Tools[现有受限工具 + skill_resource]
    Tools --> Store
```

#### 统一注册源

新增 app/skills 域：router、service、repository、schemas，以及 registry、package 校验组件。Web 与 Runner 读取同一技能注册库与共享资源路径，替换静态名称表和缓存；内置定义通过幂等迁移登记。

Web 容器中的 /app/data/skills 与宿主机的项目 data/skills 使用同一数据挂载，文件属主沿用宿主机运行用户，使 Runner 可读。用户上传内容不写入 Git 仓库的 skills/。

#### 热生效与一致性

- 上传安装使用 staging 目录；检查后移入不可变版本目录，再事务写入数据库、更新 registry_revision。
- 版本目录已存在但事务失败时，该目录不进入可用索引，作为孤立资源由维护任务识别。
- 启停、默认版本和策略变更递增 registry_revision。
- 新建任务/提交运行时获取最新 revision，API 与 Runner 不依赖进程启动时导入的技能列表。
- Runner 提交时与实际执行前均验证指定版本和启用策略。可做带 revision 的缓存，不可只靠进程内 TTL。
- 运行接受后固定资源与策略快照；技能升级不改变已经开始的运行。

热生效的含义是“新任务可发现并使用新技能，无需重建镜像或重启 Runner”。它不意味着修改已经在跑的任务。

#### 会话与版本固定

- 创建会话时绑定 skill_id 和 skill_version_id；每次 agent_run 另存版本、资源摘要与实际策略快照。
- 启用新版本只改变新会话的默认选择。
- 历史会话继续原版本；旧版本保留且策略允许时可续聊。
- 用户想切换 Skill 或版本时，明确选择“基于此任务新建会话”，生成新的原生会话映射。避免直接更换提示词后继续 --resume，把两种行为混入同一上下文。
- “回退默认版本”影响后续新会话，不回写历史记录。
- 禁用技能阻止新的执行，包括历史会话再发送与排队任务真正启动；已运行任务默认完成，也可显式取消。
- 禁用后的定时任务显示“技能不可用”，记录跳过原因；重新启用不补跑历史时间段。

### 3.2 技能包格式与兼容约定

#### 支持的目录约定

```text
paper-method-review/
  SKILL.md                 必需：技能说明与指令
  skill.json               可选：本平台扩展清单
  references/              可选：按需读取的参考文档
  assets/                  可选：预览与输出示例
  templates/               可选：任务模板
  scripts/                 可保留为未执行资源；MVP 不运行
```

不要求所有已有技能都具有本平台的 skill.json。只有 SKILL.md 的包也可以进入预览，由用户补齐执行工具、预算档位和模板；无法识别的格式返回明确提示。

SKILL.md 的名称、简介等元数据可用于预填。文件内容不能自行获得权限、覆盖全局系统约束或改变上传策略。

#### 平台清单示例

以下为拟定的平台格式，不声明它是其他智能体通用格式：

```json
{
  "schema_version": 1,
  "name": "方法与实验审查",
  "slug": "method-experiment-review",
  "version": "1.0.0",
  "description": "围绕方法假设与实验支持整理可追溯的审查结果。",
  "entry": "SKILL.md",
  "task_kind": "review",
  "input_contract": { "min_papers": 1, "max_papers": 3, "pdf_required": true },
  "requested_tools": ["paper_read", "paper_page", "library_search"],
  "capabilities": { "vision_required": false },
  "budget_profile": "reading",
  "templates": [{ "name": "方法与实验审查", "file": "templates/review.md" }]
}
```

slug 不是数据库主键。用户技能由服务端分配 custom: 前缀 ID，不能通过清单冒充 paper_read 等内置技能。任务类型必须落在平台已支持的范围；特殊输入契约和预算档位都由服务端解析。

### 3.3 包校验、执行权限和参考材料读取

#### 归档检查

建议初始限制：ZIP 20MB、展开合计 100MB、最多 1000 个文件、最大目录深度 12；具体由服务端配置。检查通过才将包转入正式技能存储。

必须检查：

- 归档路径不得越过隔离目录：拒绝绝对路径、.. 穿越、盘符路径和符号/硬链接。
- 限制文件数量、解压后大小、压缩比和嵌套归档；不递归解压包中归档。
- 入口与模板资源必须存在，并在包内；不接受模板引用任意服务器路径。
- 校验名称长度、元数据格式、清单版本和所有声明工具。
- 不运行安装钩子，不执行包内脚本，不自动安装 pip/npm 依赖。
- 保存原包与规范化文件清单的 SHA-256，导入错误、启用和版本切换留审计记录。

预览文本转义后渲染；不直接执行包内 HTML。结构检查只能发现结构和权限问题，不承诺技能指令语义完全安全。

#### 工具与预算

有效工具集合 = 技能声明请求 ∩ 平台可授予集合 ∩ 用户/部署策略允许集合。

若某个必需工具无法满足，标记为不可用，不能悄悄删掉工具后宣称安装兼容。已有 paper_read、paper_page、library_search 等工具继续由 Runner 白名单与会话关联论文范围约束。paper_import 等写入工具需要专门的授权执行档位，普通阅读技能不因声明而获得写入权限。

有效预算不能超过平台硬上限。清单中的 reading 等档位是请求，最终生效参数由服务端确认并记录。包不能更改模型凭据、Runner 启动参数或全局权限。

#### 参考材料的读取

当前 CLI 禁用普通工具，只开放受限 MCP；因此不能假设上传 references/ 后智能体就能直接读取。

新增受限工具 skill_resource：按运行绑定的 skill_version_id、相对路径读取文本资源，并校验路径、文件类型、版本摘要、每次字符数、累计读取量和调用次数。资源目录不可写；不能读取其他技能版本、宿主机文件或任意网络 URL。入口说明首次加载，参考资料按需读取，降低上下文开销。

scripts/ 暂不暴露执行通道。若未来需要运行脚本，另行设计工具适配、隔离执行和网络/文件访问边界；不通过单个“允许执行所有脚本”开关实现。

### 3.4 数据模型与兼容迁移

使用下一编号的数据库迁移新增以下实体，保留现有论文与会话 ID。

| 表或扩展 | 主要字段 | 约束与职责 |
|---|---|---|
| skills | id、owner_id、name、description、source、status、default_version_id、created_at | 内置/用户技能统一管理；状态 enabled / disabled / archived |
| skill_versions | id、skill_id、version、content_hash、storage_key、entry、manifest_json、validation_status、created_at | 同一技能版本号唯一；内容不可覆盖；validation_status 为 validated / incompatible；坏包不产生可安装版本 |
| skill_categories | id、owner_id、name、sort_order | 独立于论文和会话分类；归一化名称在 owner 内唯一 |
| skill_category_items | skill_id、category_id | 多对多、组合唯一 |
| skill_tags / skill_tag_items | tag_id、name / skill_id、tag_id | 标签复用与检索 |
| skill_imports | id、owner_id、filename、archive_hash、status、report_json、result_version_id、request_key、created_at | uploading / validating / awaiting_config / installed / rejected / failed；幂等导入 |
| skill_audit_events | id、actor_id、skill_id、version_id、action、detail_json、created_at | 安装、启停、回退、归档和配置变更 |
| skill_registry_state | singleton_id、revision | 动态目录修订号 |
| user_profiles | id、display_name、avatar_storage_key、auth_subject | MVP 一名本地用户；auth_subject 不由上传表单指定 |
| user_preferences | user_id、preferences_json、revision、updated_at | 偏好设置及乐观锁 |
| conversations 扩展 | skill_version_id | 固定会话技能版本；现有 skill 字段保留兼容 |
| agent_runs 扩展 | skill_version_id、skill_hash、execution_policy_json | 保存实际执行版本与策略快照 |
| task_templates 扩展 | skill_version_id、source_template_key | 版本模板关联；安装幂等，不重复生成模板 |

关键约束：

- default_version_id 必须属于当前 skill；启用必须指向完整且兼容的版本。
- 被会话、运行或模板引用的技能版本不能物理删除。MVP 只提供禁用与归档，不提供级联删除。
- 相同包摘要重复导入返回已有结果；同技能同版本但内容不同返回冲突，不覆盖。
- owner_id 由服务端身份解析，不能相信客户端提交的 owner_id。MVP 字段预留不代表已具备多租户隔离。
- 分类重命名和默认版本更新采用 revision/updated_at 校验，冲突返回 409。

补充：新增功能不把论文入库 ready 状态作为“已读”。阅读进度筛选若需持久化业务状态，应另定字段或明确由已有 reader_states 推导的规则。上下文若支持多篇论文提及，应同步修改运行与草稿的前后端 schema，并兼容旧 SelectionContext 和 attachment_ids。

### 3.5 接口设计与执行契约

以下为新增或调整的设计接口，不是当前已上线 API。

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | /api/skills/imports | 上传 ZIP，返回导入 ID；仅进入检查，不调用模型 |
| GET | /api/skills/imports/{id} | 读取结构检查进度、候选元数据和问题 |
| POST | /api/skills/imports/{id}/install | 确认补充信息，安装为未启用版本；request_key 幂等 |
| GET | /api/skills | 按分类、标签、状态、来源、关键词分页查询 |
| GET | /api/skills/{id} | 技能详情、默认版本、能力与使用摘要 |
| PATCH | /api/skills/{id} | 名称、分类、标签与归档等元数据 |
| POST | /api/skills/{id}/enable | 校验工具/能力/预算策略后启用；写审计 |
| POST | /api/skills/{id}/disable | 禁止后续执行；不自动取消在途运行 |
| GET | /api/skills/{id}/versions | 历史版本与引用信息 |
| POST | /api/skills/{id}/default-version | 选择默认版本或回退；带预期 revision |
| GET | /api/skills/{id}/versions/{vid}/resources | 列举允许预览的资源；不暴露宿主绝对路径 |
| GET / POST / PATCH / DELETE | /api/skill-categories、/api/skill-categories/{id} | 分类查询、新建、修改和解除归类 |
| POST | /api/skills/{id}/validate-run | 用户显式触发最小执行验证，复用 agent_runs |
| GET | /api/me | 用户展示信息、身份模式与可用菜单能力 |
| PATCH | /api/me | 更新显示名等资料 |
| POST | /api/me/avatar | 校验并保存用户头像 |
| GET / PATCH | /api/me/preferences | 获取/更新偏好；revision 乐观锁 |

现有接口调整：

- /api/sessions：创建会话接受 skill_id、可选 skill_version_id、template_id；必须校验模板与版本兼容。
- /api/agent/runs：版本从会话绑定解析，客户端不能覆盖已绑定版本或硬上限。
- /api/agent/status：增加 registry_revision、可用技能摘要及真实能力信息。
- Runner 私有 /runs 请求：增加精确 skill_version_id、skill_hash、策略快照；Runner 独立校验允许范围，不直接相信 Web 请求里的权限。
- GET /api/sessions/templates 保持兼容返回结构，并补充版本、来源、可用性；禁用版本不再作为新建任务候选。

错误约定：413 包过大，422 包结构/兼容性错误，409 重复版本冲突或并发修改，404 资源不可见，403 操作不允许。检查报告按文件列出问题，避免只有笼统“上传失败”。

追加界面接口要求：

- 历史运行分页优先复用已有 sessions runs 游标接口，ChatPanel 增加向上加载入口。
- 先复用已有会话列表筛选；全库会话内容搜索若缺少接口，单独增加服务端检索，不把当前页前端过滤当作全库搜索。
- 运行状态以现有取消接口和 SSE 为基础，新增 UI 不另造执行协议。
- 用量缺失时显示未提供；累计、上下文占用、估算和实际费用在接口语义上分开。
- 权限交互只有 Runner 真正提供可处理事件时才开放，不在前端伪造授权能力。

### 3.6 存储、备份与部署

```text
data/
  skills/
    staging/<import_id>/
    archives/<archive_hash>.zip
    packages/<version_id>/...
  avatars/<asset_id>
```

SQLite 管理生命周期、默认版本和引用；文件系统保存不可变包资源。目录必须同时被 Web 与宿主 Runner 读取，权限不得使其他本地用户任意修改正在使用的版本。导入暂存有过期清理，正式版本不按最后访问时间随意清除。

备份增加技能注册表、原包、展开资源和头像；恢复时对照资源摘要检查一致性。用户偏好不包含模型密钥；凭据继续放现有宿主机配置。

首次引入动态注册需要部署 Web 与 Runner 协议变更；之后正常上传/启停技能无需重启。部署期间旧协议的兼容读取只适用于明确的内置技能映射，不能将未知自定义技能降级成 chat。

| useSkillsStore | 列表、分类、revision 与导入状态；不复制执行权限逻辑 |
| useUserStore | 用户资料、偏好、能力标记 |
| useRunStore / ResearchComposer | 共用既有运行生命周期、草稿、附件、停止和进度展示 |

设置页、技能库和论文库使用统一的固定导航 + 自适应内容区，显式区分导航高度与滚动内容，避免此前 flex 规则将导航拉伸占满半屏的问题。

聊天组件进一步拆分为：

| 组件 | 职责 |
|---|---|
| SessionHeader | 当前论文、会话、技能版本、详情入口 |
| RunTranscript | 消息渲染、来源定位、工具折叠、历史分页与滚动锚点 |
| RunStatus | 当前运行状态、耗时、停止与连接反馈 |
| ResearchComposer | 文本、模板菜单、草稿、发送与运行时编辑 |
| ContextAttachments | 论文提及、原文选区、图片、上传与移除状态 |

原 ChatPanel 保留为协调容器，逐步提取 composable；Activity store 与聊天共用按 run_id 管理的订阅层，避免两套状态各自判断终态。保留 SSE 与轮询兜底，状态变更由统一订阅层更新。

### 3.8 统一实施阶段、依赖与交付门槛

| 阶段 | 工作包 | 依赖 | 可交付结果/门槛 |
|---|---|---|---|
| A：合同与基础交互 | 固定接口/schema、状态词、功能编号；用户菜单与设置壳层；当前运行停止入口 | 现有框架与任务 API | 用户可找到管理入口，导航收起仍可停止；身份模式和未实现菜单真实可见 |
| B：技能注册基础 | 数据迁移、内置技能登记、Registry、不可变资源与策略快照；分类与只读技能库 | A 的契约 | 原内置任务兼容；Web 与 Runner 读取同一注册源，版本固定 |
| C：技能包完整闭环 | ZIP 暂存/校验/预览/安装/启用、skill_resource、任务与模板接入、审计和备份 | B | 不重启即可新增技能；一次最小实际执行成功；旧会话仍使用原版本 |
| D：研究交互整合 | 会话导航、/ 模板、@ 论文、粘贴/拖放、统一上下文、长对话分页与滚动 | A；技能选择部分依赖 C | 历史任务可召回，输入上下文完整，切换不丢草稿，上翻不抢滚动 |
| E：界面一致性与成果 | 用量摘要、标签状态、布局预设、论文库密度与筛选、Markdown 导出、移动端完善 | D 和稳定的数据契约 | 所有状态一致、来源可追溯、窄屏无溢出 |
| F：高级能力 | 真正增量、原生分支、技能组合、工具适配、知识联动等 | A–E 验收 | 每项另行定义协议、预算、能力与验收，不混入 MVP 完成声明 |

P0 的正式交付门槛是 A–C 完整贯通。A 中纯 UI 与既有取消入口不需要数据库迁移；B、C 必须迁移数据库并协调 Web/Runner 协议，不能沿用“整个 P0 不改数据库”的旧假设。

阶段内的串行依赖：数据/协议先于热加载；Registry 先于启用；资源读取先于使用 references；会话版本绑定先于实际执行；安装与启用完成后才向任务选择器开放。界面样式与独立组件可先准备，但不可把未接通功能显示为可用。

### 3.9 详细迁移与发布步骤

1. 增加技能、版本、分类、导入记录和用户偏好表；幂等登记现有八个内置技能，保留原技能 ID。
2. 为原会话绑定对应内置版本。历史运行仅在可证明版本一致时回填；无法确认时保留历史版本未知标记，不伪造摘要或快照。
3. 将 API 与 Runner 的静态 SKILLS 校验迁移到同一 Registry；保留内置别名兼容，验证原有导入、阅读、审查、比较和定时任务。
4. 加入不可变资源、上传隔离与结构检查，先验证不调用模型的完整安装过程。
5. 加入用户入口、技能库、分类、版本详情及任务选择。
6. 仅选择一个小技能，用现有智能体做一次最小验证，再测试热启用、停用和版本固定。
7. 补充备份内容、恢复说明、失败清理和审计查询，随后发布。

旧数据迁移与新技能安装分开，便于回退。回退到不支持动态技能的旧镜像前必须停用新技能相关新执行，不能假设旧版本能识别新增 Skill。

补充界面迁移：先保留现有事件与组件外壳，逐个迁移输入、订阅和消息展示；每迁移一项就验证关联论文、会话绑定、页码/缩放/辅助区、未发送文字及附件恢复。设置偏好与工作区现值的优先级按 2.2 执行，不在升级时静默覆盖用户布局。

每次发布保留已知可用镜像与对应备份，沿用现有 app、Qdrant、backup 和宿主 Runner 拓扑。纯界面发布不重启 Runner；引入 Registry 的首次发布需要协调升级 Web 与 Runner，避免一边动态、一边静态。

### 3.10 联合验收矩阵

| 场景 | 可验收结果 |
|---|---|
| 正常 ZIP | 能预览、补全配置、安装为未启用状态 |
| 只有 SKILL.md | 可进入元数据补全，不强制已有平台清单 |
| 非法包 | 穿越路径、链接、超限展开、缺入口等被拒绝，正式目录不受影响 |
| 重复导入 | 相同包返回已有结果；同版本不同内容返回冲突 |
| 动态启用 | 不重启 Web/Runner，新任务即可选择；禁用立即阻止后续启动 |
| 分类 | 可创建、改名、筛选、多分类；删除分类后技能与历史记录完整 |
| 资源读取 | 只读取当前运行绑定版本的允许资源；跨版本和越界访问失败 |
| 历史会话 | 新版本不改变旧会话；切换技能/版本会明确新建会话 |
| 在途运行 | 升级/禁用不篡改已开始运行；取消走现有取消机制 |
| 任务约束 | 缺 PDF、论文数不符、缺必需工具/视觉能力时发送前给出明确提示 |
| 用户入口 | 桌面和手机均可找到技能库/设置；没有认证能力时不展示假退出 |
| 成本 | 上传、检查、分类、预览零模型调用；一次最小真实技能验证记录用量与结果 |
| 备份恢复 | 技能版本、资源摘要、模板、会话和运行引用能共同恢复 |
| 布局 | 桌面和窄屏无横向溢出，导航保持正常高度，操作不覆盖输入框 |

界面与任务链路追加验收：

| 对应功能 | 场景 | 验收要求 |
|---|---|---|
| F02 | 同论文多个任务 | 论文主项打开 PDF，任务子项恢复准确会话，不重复创建 |
| F03 | 三种图片入口 | 文件选择、粘贴、拖放共用数量/大小/类型校验；失败可见，可移除 |
| F03、F08 | 模板与技能切换 | 当前模板只填文字；切到其他技能明确新建会话，不混入旧原生上下文 |
| F03 | 运行时编辑 | 可写下一条草稿，终态不清除；未经用户发送不新增执行 |
| F04 | 取消与断线 | 导航收起仍可取消；断线显示连接状态，不伪造任务失败或重放 |
| F04 | 向上读历史 | 新消息/终态不强制滚到底部；分页无重复，视口锚点保持 |
| F05 | 多标签 | 状态标记准确；切换保留阅读与草稿；关闭只影响视图 |
| F06 | 用量与能力 | 缺失显示未提供；估算有标识；不以 tokens 总和伪装上下文窗口占用 |
| F09 | 论文库 | 主操作清晰，批量条按选择出现；缺全文保留定向导入；长内容不撑开布局 |
| F10 | 错误、保存与导出 | 网络错误不显示成空数据；保存失败不显示成功；导出保留来源标识 |
| 全局 | 桌面与窄屏 | 导航高度正常、没有页面横向溢出；输入框和主操作不被菜单覆盖 |

验证策略：先做无模型的 schema、状态、组件和接口检查，再做真实浏览器操作。首次动态技能执行只用一个小技能做一次最小真实 Agent 验证；UI 重排、分类与导入结构检查不额外调用模型。更复杂图表理解、所有外部来源和长期记忆不纳入这一次验证的完成声明。

### 3.11 MVP 完成定义与后续交接

MVP 必须同时具备：

1. 用户菜单能进入技能库和设置，身份与可用操作真实。
2. 现有内置技能和原会话继续正常使用。
3. 一个合法技能 ZIP 能完成检查、安装、启用和分类，并在不重启的情况下被新任务发现。
4. 新任务由现有智能体执行，版本、资源和执行策略可追溯。
5. 技能升级/禁用不篡改历史和在途运行。
6. 上传和管理零模型调用，一次最小实际执行验证有用量和结果记录。
7. 桌面/窄屏可用，备份与回退路径明确。

P1 按 D–E 交付研究交互整合，P2 按 F 独立立项。后续开发以“功能编号 → 工作包 → 接口/数据 → 验收用例”的对应关系跟踪，不再同时维护两套相互冲突的实施优先级。

本轮交付仅生成合并方案；原 D1、D2 保留作来源记录，线上服务、数据库和服务器 Git 状态不在本轮改变。
